# Java में Aspose.Tasks के साथ महत्वपूर्ण और प्रयास‑आधारित कार्यों का प्रबंधन

आधुनिक प्रोजेक्ट प्रबंधन में, **manage critical tasks java** डेवलपर्स के लिए एक दैनिक चुनौती है, जिन्हें शेड्यूल को ट्रैक पर रखना होता है जबकि प्रयास‑आधारित कार्य आइटम्स को संभालना पड़ता है। Aspose.Tasks for Java आपको एक साफ़, प्रोग्रामेटिक तरीका प्रदान करता है जिससे आप महत्वपूर्ण और प्रयास‑आधारित कार्यों की पहचान, निरीक्षण और अपडेट कर सकते हैं, बिना मैन्युअल स्प्रेडशीट के झंझट के।

## त्वरित उत्तर
- **मुख्य लाभ क्या है?** एक ही API कॉल में स्वचालित रूप से महत्वपूर्ण कार्यों को चिन्हित करता है और प्रयास‑आधारित शेड्यूलिंग को समायोजित करता है।  
- **क्या मुझे लाइसेंस चाहिए?** विकास के लिए एक मुफ्त ट्रायल काम करता है; उत्पादन के लिए एक व्यावसायिक लाइसेंस आवश्यक है।  
- **कौन से Java संस्करण समर्थित हैं?** Java 8 से 17, दोनों OpenJDK और Oracle वितरण।  
- **क्या मैं बड़े प्रोजेक्ट्स प्रोसेस कर सकता हूँ?** हाँ – Aspose.Tasks 10 000 तक कार्यों वाले प्रोजेक्ट्स को कुशलता से संभालता है।  
- **क्या यह क्रॉस‑प्लेटफ़ॉर्म है?** लाइब्रेरी Windows, Linux, और macOS पर बिना नेटिव डिपेंडेंसीज़ के चलती है।

## Aspose.Tasks for Java में महत्वपूर्ण और प्रयास‑आधारित कार्यों का प्रबंधन कैसे करें?
`Project` क्लास का उपयोग करके अपने प्रोजेक्ट फ़ाइल को लोड करें, सभी कार्यों को इकट्ठा करने के लिए `ChildTasksCollector` का उपयोग करें, और फिर प्रत्येक कार्य की `Critical` और `EffortDriven` प्रॉपर्टीज़ की जाँच करें। एकत्रित सूची पर इटररेट करके आप एक स्टेटस रिपोर्ट बना सकते हैं या शेड्यूलिंग नियमों को स्वचालित रूप से संशोधित कर सकते हैं, वह भी कुछ ही लाइनों के Java कोड से जो सेकंडों में चल जाता है।

Aspose.Tasks for Java **30+ इनपुट और आउटपुट प्रोजेक्ट फॉर्मेट्स** (जैसे Microsoft Project 2019, 2022, और Primavera P6) का समर्थन करता है और **10 000 तक कार्यों** वाली फ़ाइलों को प्रोसेस कर सकता है, जबकि सामान्य सर्वर पर मेमोरी उपयोग 200 MB से कम रहता है। ये मापी गई क्षमताएँ इसे एंटरप्राइज़‑स्तर की योजना के लिए उपयुक्त बनाती हैं।

## पैकेज आयात करें
अपने Java स्रोत फ़ाइल में आवश्यक नेमस्पेस जोड़ें:

```java
import com.aspose.tasks.*;
import java.util.*;
```

ये इम्पोर्ट्स आपको `Project`, `Task`, और यूटिलिटी हेल्पर्स जैसी कोर टास्क‑मैनेजमेंट क्लासेज़ तक पहुंच प्रदान करते हैं।

## महत्वपूर्ण कार्य क्या है?
एक **critical task** वह कोई भी गतिविधि है जिसका विलंब सीधे प्रोजेक्ट की समाप्ति तिथि को बढ़ा देता है, अर्थात यह शेड्यूल के critical path पर स्थित होता है। Aspose.Tasks में, आप `Task.isCritical()` मेथड को कॉल करके यह निर्धारित कर सकते हैं कि कोई कार्य critical है या नहीं, जो तब `true` लौटाता है जब कार्य समग्र प्रोजेक्ट पूर्णता समय को प्रभावित करता है।

## प्रयास‑आधारित कार्य क्या है?
एक **effort‑driven task** अपनी अवधि बदलने पर अपने शेष कार्य को स्वचालित रूप से पुनर्वितरित करता है, जिससे शेड्यूल के दौरान कुल प्रयास स्थिर रहता है। यह व्यवहार उन संसाधनों के लिए उपयोगी है जो निश्चित दर से काम करते हैं। Aspose.Tasks में, `Task.isEffortDriven()` प्रॉपर्टी उन कार्यों के लिए `true` लौटाती है जो इस विशेषता को प्रदर्शित करते हैं।

## चरण 1: ChildTasksCollector का उपयोग करके कार्य एकत्र करें
`ChildTasksCollector` क्लास दिए गए पैरेंट टास्क के नीचे सभी कार्यों को एकत्र करती है।  

`ChildTasksCollector` एक हेल्पर है जो टास्क हायरार्की को ट्रैवर्स करता है और `Task` ऑब्जेक्ट्स की एक फ्लैट लिस्ट लौटाता है।

```java
ChildTasksCollector collector = new ChildTasksCollector();
TaskUtils.apply(project.getRootTask(), collector);
List<Task> allTasks = collector.getTasks();
```

## चरण 2: एकत्रित कार्यों पर इटररेट करें
सूची पर लूप करें और प्रत्येक कार्य की critical और effort‑driven स्थिति को प्रिंट करें।

```java
for (Task t : allTasks) {
    boolean isCritical = t.get(Tsk.Critical);
    boolean isEffortDriven = t.get(Tsk.EffortDriven);
    System.out.println("Task ID " + t.get(Tsk.Id) + 
        ": critical=" + isCritical + ", effortDriven=" + isEffortDriven);
}
```

यह सरल दो‑चरणीय पैटर्न आपको प्रोजेक्ट की शेड्यूलिंग स्वास्थ्य का पूर्ण दृश्य देता है।

## सामान्य समस्याएँ और ट्रबलशूटिंग
- **NullPointerException on task properties** – कार्यों तक पहुंचने से पहले सुनिश्चित करें कि प्रोजेक्ट फ़ाइल पूरी तरह लोड हो (`project = new Project("file.mpp")`)।  
- **Incorrect critical flag** – सुनिश्चित करें कि प्रोजेक्ट का कैलकुलेशन मोड `CalculationMode.Automatic` पर सेट है ताकि Aspose.Tasks संशोधनों के बाद critical path को पुनः गणना कर सके।  
- **Large files cause slowdown** – फ़ाइल को रीड‑ओनली मोड में खोलने के लिए `Project.set(Prj.ReadOnly, true)` का उपयोग करें, जो रीड‑ओनली विश्लेषण के लिए मेमोरी ओवरहेड को कम करता है।
